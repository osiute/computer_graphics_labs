# Лабораторная работа №16. OBJ и материалы MTL

Приложение C++17 читает полигональную модель OBJ, находит связанные библиотеки MTL, назначает граням цвета `Kd` и сохраняет изображение с закрашенными поверхностями в PNG. Ракурс, размеры изображения и путь результата задаются в консоли. Результат можно открыть обычным просмотрщиком изображений или в VS Code.

## Сборка и запуск

Нужны компилятор C++17, CMake и средство сборки (например, GCC и Make в Linux/WSL). Для отладки из прилагаемой конфигурации VS Code нужен GDB. Все команды этого раздела выполняются из корня репозитория:

```bash
cmake -S lab16 -B lab16/build -DCMAKE_BUILD_TYPE=Debug
cmake --build lab16/build
ctest --test-dir lab16/build --output-on-failure
./lab16/build/lab16_app lab16/assets/house.obj lab16/build/house.png 35 25 1000 800
```

Откройте `lab16/build/house.png`, чтобы увидеть результат. Файл PNG создаётся самим приложением; внешний конвертер изображений не требуется.

Интерактивный запуск:

```bash
./lab16/build/lab16_app
```

Программа последовательно запрашивает путь OBJ, путь PNG, азимут, угол возвышения, ширину и высоту. Нажатие Enter выбирает предлагаемое значение. Исходная модель по умолчанию — `assets/house.obj` внутри `lab16`; она находится и при запуске из каталога сборки. Для произвольных файлов можно вводить абсолютные пути. Относительные пользовательские пути отсчитываются от текущей рабочей директории.

Режим с аргументами:

```text
lab16_app [model.obj] [output.png] [azimuth elevation [width height]]
lab16_app --help
```

После имени программы допускается 1, 2, 4 или 6 позиционных аргументов. Без аргументов используется интерактивный режим. Углы задаются в градусах. Значения по умолчанию: азимут `35`, возвышение `25`, ширина `1000`, высота `800`. Например, другой ракурс той же модели:

```bash
./lab16/build/lab16_app lab16/assets/house.obj lab16/build/house_other.png -35 15
```

При сборке генератором Visual Studio в Windows исполняемый файл обычно находится в `lab16/build/Debug/lab16_app.exe`. Используйте `cmake --build lab16/build --config Debug`, а при запуске указывайте этот путь. Для MinGW исполняемый файл обычно лежит непосредственно в `lab16/build` и имеет расширение `.exe`.

## Работа в VS Code

Прилагаемые `.vscode/tasks.json` и `.vscode/launch.json` рассчитаны на открытие папки **`lab16` как рабочей папки**, Linux или WSL и GDB.

1. Откройте `lab16` через **File → Open Folder**. В WSL откройте её в окне VS Code, подключённом к WSL.
2. Установите рекомендуемые расширения C/C++ и CMake Tools.
3. Нажмите **Ctrl+Shift+B**: задача `lab16: build` выполнит настройку CMake и сборку.
4. Выполните **Terminal → Run Task → lab16: render house**. Откройте `build/house.png` в редакторе.
5. Для автоматических проверок выберите `lab16: test`.
6. Для отладки поставьте точку останова, выберите `lab16: house (Linux / WSL, GDB)` и нажмите **F5**. Ракурс и имя результата можно менять в `args` файла `launch.json`.

В терминале VS Code, открытом в `lab16`, интерактивная программа запускается командой `./build/lab16_app`. На Windows вне WSL настройте отладчик под выбранный компилятор: для MSVC нужен `cppvsdbg`, для MinGW — путь к его `gdb.exe`; также замените путь к программе в задачах и конфигурации запуска на фактический путь `.exe`.

## Пример модели и материалов

Геометрия `assets/house.obj` взята из `lab15/obj/house.obj`: все 10 вершин и 7 граней сохранены без изменений. Добавлены `mtllib house.mtl` и назначения материалов `usemtl`. Библиотека примера содержит четыре материала:

| Материал | Назначение | `Kd` |
| --- | --- | --- |
| `Walls` | Пятиугольные торцевые стены | `0.86 0.67 0.36` |
| `Sides` | Боковые стены | `0.25 0.48 0.72` |
| `Roof` | Скаты крыши | `0.72 0.24 0.16` |
| `Foundation` | Нижняя грань | `0.40 0.43 0.48` |

Для демонстрации зависимости цвета от MTL измените, например, строку материала `Roof` на `Kd 0.15 0.75 0.25`, сохраните MTL и повторите запуск с тем же ракурсом. Крыша должна стать зелёной; пересборка программы не нужна. Сохраните результаты под разными именами, затем верните исходный `Kd` для стандартного примера.

Путь MTL отсчитывается от папки OBJ. При перемещении примера держите оба файла рядом. `usemtl` влияет на все последующие грани до следующей такой инструкции. Если у грани нет материала, материал неизвестен или библиотека не найдена, программа выводит предупреждение и использует стандартный цвет.

## Устройство программы

Загрузка OBJ/MTL, рендеринг и консольный интерфейс разделены на модули. Используются существующие `Point3D`, `Face`, `Mesh`, `Image`, `Pixel` и `apply_perspective` из `common_utils`. Существующая каркасная отрисовка остаётся доступной другим лабораторным. Закрашивание и запись PNG находятся в `lab16`.

Загрузчик распознаёт вершины `v`, координаты `vt`, нормали `vn`, грани `f`, `mtllib` и `usemtl`. У индексов поддерживаются формы `v`, `v/vt`, `v//vn`, `v/vt/vn` и отрицательные значения относительно уже прочитанных соответствующих элементов. Нулевые индексы и ссылки вне диапазона являются ошибками. Из MTL для цвета используется `newmtl` и `Kd`; другие свойства не участвуют в изображении.

Перед отображением модель центрируется и масштабируется до радиуса 100. Затем применяется выбранный поворот и общая перспективная проекция, в которой камера учитывает смещение по глубине на 500. Простые многоугольники, в том числе вогнутые, разбиваются на треугольники методом отсечения ушей после проекции на доминирующую координатную плоскость. Для каждого пикселя треугольника интерполируется обратная глубина; Z-буфер оставляет ближайшую поверхность. Поэтому порядок граней в файле не определяет видимость.

Цвет треугольника — `Kd` его исходной грани, преобразованный в 8-битный RGB. Освещение, текстуры, прозрачность и сглаживание нормалей не используются. Поэтому проверять `Kd` можно непосредственно по цвету внутренних пикселей поверхности. Для неплоской грани поверхность определяется полученными треугольниками; другая триангуляция может дать другую форму между исходными вершинами. Самопересекающиеся и вырожденные многоугольники отклоняются. Сложные поверхности можно заранее триангулировать в редакторе.

## Проверки перед демонстрацией

Автоматические проверки запускаются через CTest; исполняемый тестовый target называется `lab16_tests`. Для повторения проверок отдельных запусков и получения демонстрационных PNG нужен Python 3 (дополнительные пакеты не требуются):

```bash
python3 lab16/check_cli.py lab16/build/lab16_app
```

Скрипт сохраняет PNG и журнал в `lab16/results`. Изменение `Kd` выполняется во временной копии MTL, исходная библиотека остаётся пригодной для следующей демонстрации.

Проверено 20.10.2026 в Linux/WSL, GCC 13.3 и CMake 3.28: сборка успешна; CTest — 1/1, внутри него 6 групп проверок C++; отдельные запуски CLI — 15/15. Проверены все 10 моделей из `lab15/obj`, вогнутые грани, индексы OBJ, ошибки входных данных и материалов, повторная загрузка после изменения `Kd`, ракурсы включая ±90°, запись и обратное чтение PNG с точным совпадением всех RGB-пикселей. Видимость сверена с независимыми пересечениями лучей с треугольниками для 28 800 пикселей; проверена независимость от порядка граней. Нативные Windows-сборка и импорт в Blender в этой среде не запускались.

Для ручной демонстрации:

1. Выполните сборку и CTest, сохраните вывод терминала.
2. Откройте PNG стандартного дома: проверьте разные цвета стен и крыши и отсутствие просвечивающих дальних граней.
3. Получите ещё один PNG с другим ракурсом и проверьте перекрытия.
4. Измените `Kd` крыши, повторите запуск и сравните оба файла; затем восстановите материал.
5. Введите заведомо отсутствующий OBJ: программа должна сообщить ошибку чтения.
6. Скопируйте `house.obj` во временный каталог без `house.mtl`: программа должна предупредить об отсутствующей библиотеке и сохранить изображение стандартного цвета. Не удаляйте исходный MTL ради проверки.
7. Для проверки неправильного индекса создайте отдельный тестовый OBJ с `f 0 1 2` или ссылкой на отсутствующую вершину: загрузка должна завершиться понятной ошибкой.

## Изображение в Blender и материалы отчёта

Откройте Blender и импортируйте **тот же** `assets/house.obj` через импорт Wavefront OBJ. Убедитесь, что рядом находится `house.mtl`. Если импортёр предлагает оси, для этой модели используйте `Y` как ось вверх; при необходимости выберите направление вперёд `-Z`. Модель должна стоять на основании. Подберите близкий ракурс и включите **Material Preview**. В списке материалов должны быть `Walls`, `Sides`, `Roof`, `Foundation`.

Blender может изменять видимые оттенки из-за освещения и управления цветом; назначение материалов и геометрию сравнивайте отдельно от точного совпадения RGB. В режиме Solid по умолчанию могут отображаться служебные цвета вместо материалов. Если используете Solid, включите окраску по материалу и проверьте настройки **Viewport Display**; для проверки импорта `Kd` предпочтительнее Material Preview и свойства материала.

Для отчёта нужны реальные снимки: терминал с запуском и изображение нашей программы; Blender с импортированной моделью; при необходимости — результат изменения `Kd`. Не заменяйте снимок Blender изображением нашего рендера. Шаблон отчёта с местами для этих материалов находится в `REPORT.md`. Ссылку на репозиторий необходимо дополнить ссылкой на фактически опубликованный коммит или ветку после отправки изменений.
